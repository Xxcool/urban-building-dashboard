# Blender MCP 烘焙样区结果 v25

已通过真实MCP stdio调用本机Blender插件，完成A1框架、石材、铜色侧板、屋面及广场的UV2、AO、间接光、工程保存和GLB导出。三张终稿不变；主页面尚未替换为样区。

## 实际资产与验证

- 资产：assets/baking-pilot/v25，操作：assets/mcp-operations/v25。
- AO为2048×2048，内嵌GLB；间接光为1024×1024线性8位PNG，外载约0.55MB；高精度EXR仅在本地work保留。
- GLB约11.09MB，必要材质已打包的Blender工程约7.4MiB。
- Cycles烘焙使用Apple M1 GPU；修订后AO耗时约9.45秒，间接光约50.51秒。
- 车辆、水体、人形在烘焙遮挡集合中排除，导出恢复显示；独立业务ID仍保留。
- checks/bake-pilot-assets-v25.json核对5个UV2接收对象、AO绑定和实际文件哈希。
- checks/bake-pilot-web-v25.json记录网页3种模式和整屏测量；1880×1058实际渲染画布下，帧间隔P95约33.8ms，48 draw calls。该数据是本机技术样区，不能替代主页面GTAO与完整交互性能结果。
- 对照基线为同一模型关闭烘焙的实时材质，未启用主页面GTAO；不能据此宣称比主页面更快。
- 主园区和城市经MCP临时导出核对：二进制和业务JSON一致，仅忽略MCP自动加入的连接状态。主GLB没有覆盖，已同步当前规划及运行清单。

## 同条件视觉差异

截图为1920×1080对照画布，左侧终稿、右侧实际场景；见checks/bake-both-v25.png、bake-plain-v25.png、bake-ao-v25.png。

1. 裙房檐下、框架接缝与广场接触处增加了烘焙遮蔽，间接光用于补充静态漫反射层次。当前距离未见明显大面积UV错位；近距离及压缩后接缝仍需随模型深化继续检查。
2. 构图尚不一致：当前塔楼位置、投影高度与前景覆盖需要按终稿进一步校准；样区截图保留此差异，没有改终稿迁就模型。
3. 幕墙仍使用旧表面图集，窗格反射与室内层次重复；铜色竖梃及裙房沿街界面需按终稿深化。
4. 背景仍有过多白色体块，缺少终稿的城市层次、道路沿线和景观密度；天空也未还原终稿。
5. 原始主场景约50ms的P95问题仍单独保留，不把样区33.8ms当成该问题已修复。

结论：MCP和烘焙技术路径通过；终稿视觉还原未通过，因此未扩展三层、未启用到主页面。
