## 整屏阶段需补齐的交接内容

- 本轮不选方向、不重绘。用户确认须明确A/B及覆盖的层级；只确认一层则只记录该层。方向确认与问题关闭分别记录，不能用批准风格替代修正后的核对。
- 继续整屏设计时，按选定视觉生成园区与楼宇完整画面，修正上表内容；统一对象、文案、指标、图例、标签、导航和返回关系。正常、选中与确有需要的无数据状态纳入设计；不为凑状态新增告警、回放或房间下钻。
- 目标应用画布来自规划源。现有PNG是概念输入，不是原生1080p整屏交付；不直接拉伸或截取整张图冒充实现。
- 当前没有实际屏幕物理尺寸、观看距离和目标GPU，字号可先按目标画布校核，硬件性能和实际视距可读性须明确保留未测项。

## 建模前的制作规格与构图检查

整屏基准锁定后再填写实际数值与版本，当前只列准入要求，不提前用概念提示词中的40度视角作为定值。

| 项目 | 唯一规划源需记录 | 检查要求 |
| --- | --- | --- |
| 空间与尺度 | 单位、原点、轴向、楼栋ID、关系、坐标、主结构尺寸及依据；真实资料、设计设定、视觉估计分开 | 一组明确锚点贯通模型、标签和网页；尺寸来源不足时标为估计，不承诺工程还原 |
| 每层相机 | 正交/透视选择、位置/目标、投影参数、构图锚点、目标视口 | 园区和楼宇各有相机，但复用同一对象与空间关系；单图有透视矛盾则先处理矛盾 |
| 屏幕构图 | UI占位、安全边界、场景可见区域、主体投影位置、标签锚点与遮挡规则 | 不以整模型包围盒居中代替构图；A双栏或B左栏的占位均须纳入 |
| 资产与材质 | 主次模型细节、独立交互对象、共享/实例化/LOD、材质分区、灯光与烘焙用途 | 不烘焙动态文字、数据、选择状态；共享资产仍保持业务实例身份 |
| 性能与运行 | 目标环境、加载策略、预算、适用动态要求及测量条件 | 数值在实际工具链和目标环境核对后确定，不能凭GLB大小判定流畅 |

执行次序：检查Blender/本机脚本与网页工具能力 → 将规格写入唯一规划源并同步版本 → 脚本生成简化模型 → 在目标网页视口验证投影、坐标转换、主体比例、标签与UI留白 → 保存与设计基准的对照和差异记录 → 构图通过后深化模型。

简化模型仅用于制作验证；不得替代概念图、整屏稿或最终模型品质。相机拟合或反投影仅在投影假设成立时使用。规格文档从规划源引用，不另写一份坐标与相机参数。

## 每版修复与交付证据

每层每版保存“左：对应设计基准；右：当前模型渲染或网页截图”。同视口、同相机、同状态/数据帧、同色彩条件，注明版本；允许不同层级采用各自已锁定相机，不混用园区总览和楼宇近景的比较条件。

按大构图/相机/比例 → 几何 → 材质灯光 → UI文字图表 → 标签数据 → 交互动效顺序处理。每条记录ID、区域、预期、实际、原因假设、源修改、重建产物、复验证据、结果和下一步。轮廓错位时加边缘叠图；局部细节采用同区域等比例裁切；光照可加区域亮度/颜色统计。比较产物由项目脚本生成，记录输入版本和参数，不用像素分数替代视觉或业务验收。

修改生成源并重建后，在同条件下复验；不得靠增加泛光掩盖几何错误，不修改设计基准来消除还原差异。若需改变已确认设计，说明原因并按影响范围重新确认。实际拾取、面板联动、资源释放和性能另做运行验证，截图不算这些项目通过。
