# v22 园区进入动效实现与复核

本轮范围为用户对《campus-entrance-proposal-v22.md》回复“可以”后授权的进入动效实现。复用既有武汉光谷背景、虚构示范园区、B浅色方案及城市/园区/A1范围，不重做调研，不替换已确认概念和整屏基准。

## 实现

唯一规划源 planning/project.json，SHA256：77b5d301adbc07b4799edeedd7faf3646457dfd057dceace520dcaadc476b6ee。production.campusEntry 派生同一动效时间线；首次2.8秒、重复1.1秒、A1返回0.6秒，减少动态偏好0.15秒。

城市定位脉冲→相机靠近→城市LOD与详细园区对齐交叠→相机落位→标签与指标分组显示。App集中驱动一条时钟，城市与园区相机按原点及1.35比例换算，交叠期间视场角一致。资源尚未就绪则在1.05秒门槛停留城市；失败显示重试，重试重新挂载加载器。首次出图先初始化车辆矩阵和着色器，再发出ready。

动画中侧栏inert、标签不可拾取；导航可取消，拖动/滚轮接管当前相机，城市重播也会取消待进入任务。后台恢复不累计巨大dt。导航从城市右上随相机收束平滑移至园区右下。未新增重复业务状态或URL参数。

## 差异与修复

- ENTRY-01：原先直接切换导致生硬；改为上述连续镜头和资源门槛。实际三种入口共用同一路径。
- ENTRY-02：初次交叠截图出现位置跳变，原因是相机位置更新后朝向未同步；CityView和SceneView均显式lookAt并更新矩阵。失败截图保留checks/entry-frames-v22a；修正截图与实际投影保留entry-frames-v22，交叠地面投影XY一致，深度Z受近远裁切面影响不要求相同。
- ENTRY-03：导航上下位置突然切换；改为跟随settle进度移动。entry-frames-v22-nav-audit记录实际导航Y坐标由19逐步至649（1280×720）。
